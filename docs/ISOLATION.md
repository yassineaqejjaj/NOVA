# Isolation d'espace : matrice des cas obligatoires (NOV-110)

ADR 001 §9 : l'isolation d'espace est un contrat testé. Ce document relie chaque cas obligatoire de NOV-110 aux tests de
chacun des trois dépôts. Il a été établi en lisant les tests de `preprod` d'ORBIT (NOV-106) et de FORGE (NOV-105), sans les
modifier ni les exécuter ici ; les tests de NOVA sont dans ce dépôt. Légende : **oui** = couvert par un test d'isolation ;
**partiel** = couvert pour une partie du cas ; **non** = aucun test d'isolation pour ce cas.

Fixtures communes : NOVA `tests/support/workspace_spaces.py` (deux espaces, deux projets chacun, un Artifact C1, C2 et C3 par
projet, un utilisateur par rôle `owner` / `editor` / `viewer` / `admin`, jetons RS256 signés par une clé de test, aucun IdP).
ORBIT : `Space` de `backend/tests/test_workspace_isolation.py` (un projet, un document, un propriétaire, un administrateur,
une clé d'agent). FORGE : `Space` de `backend/tests/workspace_support.py` (un projet, un administrateur, un éditeur, une clé
`fgk_…`, un jeu de ressources complet). Aucun des trois ne dépend d'un service d'identité.

## Manques dans NOVA

* Cas 11. Il n'existe pas de rôle de plateforme qui administre sans lire les contenus : `nova-admin` voit tout son espace. Le
  rôle distinct (ADR §9, invariant 4) est à concevoir avant d'être testable. La limite est visible dans la matrice, pas masquée.
* Cas 6. Les clés d'agent ORBIT configurées dans NOVA (`NOVA_ORBIT_AGENT_KEYS`, par `slug`) sont des réglages de l'installation,
  pas d'un espace : deux espaces dont un projet référence le même `slug` ORBIT utiliseraient la même clé. À rattacher à un
  espace avec le ticket « comptes de service et clés ».
* Les runs entrants de FORGE s'exécutent dans l'espace par défaut tant que FORGE ne porte pas d'espace.

## Manques dans ORBIT et FORGE (non modifiés ici)

* ORBIT : export (rapport de conformité, export des jugements) ; suppression entre espaces (aucune assertion) ; événements
  entrants et rejouement ; jobs d'ingestion, connecteurs et rétention ; fixtures sans deux projets, sans documents C1-C3, sans
  rôles éditeur et lecteur ; rôle de plateforme sans lecture de contenu ; démonstration qu'un filtre retiré fait échouer un test.
* FORGE : événements et webhooks ; second projet par espace (isolation entre projets d'un même espace), documents C1-C3, rôles
  lecteur, évaluateur et mainteneur ; rôle de plateforme sans lecture de contenu ; démonstration qu'un filtre retiré fait
  échouer un test.
* Les deux : jeton signé par une clé de test avec `orion_workspace_id` et `orion_project_id` (en attente de leur OIDC) ; suite
  complète sous `enforce` non vérifiée.
