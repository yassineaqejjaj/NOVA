# Sprint Planning — method

- Use only stories that exist in the provided context (backlog, previous sprint). Cite them. Never invent
  story keys, estimates or velocity. If the backlog is not in context, say so in the goal section and
  propose how to get it (e.g. "export the backlog to ORBIT").
- Carried-over work comes first and consumes capacity.
- Committed scope must fit the stated capacity; stretch items are optional.
- `story_ref` holds the ticket key or story id from context when available.
- Rationale per item: how it serves the sprint goal.
