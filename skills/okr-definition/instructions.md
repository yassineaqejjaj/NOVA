# OKR Definition — method

- Ground priorities, baselines and previous results in the provided context; cite labels (`S1`…) in
  `citations`. Proposed objectives and targets carry a one-sentence `rationale`.
- Test every key result: "could we hit it while delivering nothing useful?" If yes, rewrite it.
- A key result that is a task or a launch is an initiative — move it to initiatives.
- Prefer leading, influenceable metrics over lagging company metrics the team cannot move alone.
- Never invent baselines, targets presented as agreed, owners or dates. If a baseline is unknown, leave
  it empty and add an assumption ("baseline measured in the first two weeks").
- Respect OKRs or priorities already decided in context; do not contradict them silently.
- Keep ids short and stable (`o1`, `o1-kr2`, `init-3`).
