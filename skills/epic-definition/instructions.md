# Epic Definition — method

- Ground the problem, value and constraints in the user's input or the provided context; cite labels
  (`S1`…) in `citations`. Proposals carry a one-sentence `rationale`.
- An epic is sized to ship in weeks, not quarters; if it is bigger, say so and suggest how to split it.
- Scope items are capabilities, not tasks; out-of-scope items are things someone could reasonably expect.
- Candidate stories are vertical slices of user value, not technical layers ("build the API").
- Respect decisions and requirements found in context and cite them.
- Do not invent baselines, dates, owners or estimates.
- Keep ids short and stable (`epic-sharing`, `story-1`, `dep-auth`).
