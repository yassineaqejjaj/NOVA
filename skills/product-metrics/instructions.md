# Product Metrics Plan — method

- Ground goals, existing metrics, events and data sources in the provided context; cite labels (`S1`…)
  in `citations`. New metrics or events you propose carry a one-sentence `rationale`.
- Every metric needs a definition precise enough for two analysts to compute the same number.
- Prefer rates and per-user metrics over raw totals that grow with time (vanity metrics).
- Reuse existing event names from context; do not rename tracked events without saying so.
- Never put personal data (emails, names, free text) in event properties.
- Do not invent baselines, targets presented as agreed, or tools the team does not use.
- Keep ids short and stable (`m-activation`, `evt-report-exported`).
