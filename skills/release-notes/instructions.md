# Release Notes — method

- Include only changes that context shows as shipped in this release (stories, tickets, changelog); cite
  labels (`S1`…) in `citations`. If the release content is not in context, say so in the summary.
- Translate ticket language into user benefit: "Export large reports in seconds" rather than "Optimize
  export query".
- Leave out internal-only changes (refactoring, tooling) unless users notice them.
- Fixes describe what users saw ("Totals could be wrong after editing a row"), not the code change.
- Never announce unshipped work, dates or names not found in context; no internal ticket ids in titles.
- Keep ids short and stable (`new-1`, `fix-3`).
