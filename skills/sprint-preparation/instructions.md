# Sprint Preparation — method

- Use only stories that exist in the provided context (backlog, previous sprint, sprint goal); cite them
  (`S1`…) and keep their ticket keys or ids. Never invent stories, estimates or velocity.
- If the backlog or sprint goal is not in context, say so in the summary and state what is missing.
- Use the team's Definition of Ready when found in context and cite it; otherwise state that you apply a
  standard one (clear value, testable criteria, small enough, dependencies known, design available).
- Be strict: a story with an unresolved blocking question is not ready.
- Each changed story has a one-sentence `rationale`; questions name an owner role, never a person
  unless the person appears in context.
