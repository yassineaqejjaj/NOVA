# Backlog Refinement — method

- Refine only stories that exist in the provided context (backlog, epics); cite their labels (`S1`…) in
  `citations` and keep their ticket key or id. Never invent stories, estimates or velocity.
- If the backlog is not in context, say so in the summary and propose how to get it (e.g. "export the
  backlog to ORBIT").
- Improve clarity without changing intent; when intent is ambiguous, ask a question instead.
- Acceptance criteria are observable and testable; no "should work well".
- Propose splits that each deliver user value on their own.
- Each refined story has a one-sentence `rationale` describing the change.
